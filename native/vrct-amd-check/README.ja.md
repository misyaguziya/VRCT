# VRCT AMD GPU検証ツール 0.3.1

[English](README.md)

Windows x64上で、AMD Radeon GPUを使った音声認識・翻訳が動くかを確認するためのツールです。
必要なDLLと検証用モデルを同梱しています。実行中のダウンロードや外部へのデータ送信は行いません。
VRCTの設定を読み込んだり変更したりすることもありません。

## まず実行するには

1. ZIPを右クリックして「すべて展開」し、**フォルダー全体を展開**してください。
   ZIP内から直接実行せず、展開した`vrct-amd-check`フォルダーを開きます。
2. VRCTのインストール先とは別の、書き込み可能なローカルフォルダーに置いてください。
   モデルとDLLを含む一式の展開後サイズは約4.9 GiBです。ZIPと展開先の両方を置ける空き容量が必要です。
3. 古い検証ツールの実行ファイル・DLL・モデルと混ぜず、**0.3.1一式**を使ってください。
4. 普段のAMD Adrenalinドライバーを使ってください。この検証のためにHIP SDKを追加する必要はありません。
5. ゲームやGPU負荷の高いアプリを閉じ、`run.bat`をダブルクリックします。
6. CPUでの検証も行うため、完了まで数分以上かかることがあります。
   各子プロセスの制限時間は既定で900秒です。完了すると`Finished`と表示されます。

既定の音声は、合成音声の「Hello, how are you today?」です。
マイク音声の録音は行いません。標準の実行手順では追加設定は不要です。

## 検証後に送ってほしいもの

`run.bat`と同じフォルダーに次の2ファイルが作られます。

- `vrct_amd_check_report.txt`
- `vrct_amd_check_report.json`

この2ファイルに、次の情報を添えて検証の依頼元へ送ってください。

- GPUの製品名（例：Radeon RX 7900 XTX）
- Adrenalinドライバーのバージョン
- HIP SDKを以前からインストールしていたかどうか
- 実行中に気付いた問題や、認識・翻訳結果がおかしくないか

**FAIL・BLOCKED・途中までの結果も有用な検証データです。**
送信前にレポートを開いて内容を確認してください。ユーザー名やホームフォルダーのパスは伏せ字にしますが、
共有したくない情報が残っていないかも確認してください。ツールが自動で送信することはありません。
レポートが作られなかった場合は、表示されたエラー文を依頼元に伝えてください。

同じフォルダーで再実行するとレポートは上書きされます。前回分を残す場合は、先に別の場所へコピーしてください。
合成音声のWAVも同じフォルダーに作成されます。

## 結果の見方

| 表示 | 意味 |
| --- | --- |
| OK | その検証項目が完了しました。内容や認識・翻訳の品質も確認してください。 |
| WARN | 注意点があります。ほかの項目も含めて判断します。 |
| FAIL | 実行エラー・異常終了・制限時間超過などが発生しました。 |
| SKIP | 前提条件や任意モデルが不足するなどの理由で、実行していません。 |
| BLOCKED | 比較条件を確認できず、速度比などの判断を止めています。 |

GPUの列挙やDLLの読み込みに成功しただけでは、GPU推論の成功とは判断しません。
また、レポートを正常に保存できた場合は、FAILが含まれていてもプログラムの終了コードは0になります。
実際の判定はレポート内の各項目を確認してください。

短い合成音声による動作確認であり、長時間利用・VRChatとの同時利用・多言語の品質を保証するものではありません。
AMD対応を採用できるかどうかは、各実機の結果を集めて判断します。

## 0.3.1で追加したクラッシュ回避

CT2の子プロセスだけに`AMD_COMGR_CACHE=0`を設定し、DLLの読み込み前に確認します。
ROCm COMGRのキャッシュ処理が、非ASCII文字を含むWindowsのパスで
`LLVM ERROR: Can't get available size`を出して終了する問題への回避策です。
利用者がWindowsの環境変数を手動設定する必要はありません。

JSON・テキストの両レポートで、CT2項目の`data.ct2_comgr_cache`に状態を記録します。

| フィールド | 意味 |
| --- | --- |
| `configured_value` | 子プロセスに渡した値。0.3.1では`"0"`です。 |
| `observed_disabled` | 子側で無効化を確認できた場合は`true`、無効化されていなければ`false`、観測できなければ`null`です。 |
| `verified_before_vendor_load` | DLL読み込み前の確認を取得できた場合だけ`true`です。 |
| `environment_variable` / `scope` / `reason` | 対象の環境変数、適用範囲、回避理由です。 |

確認後に子プロセスがクラッシュしても、その確認結果とFAILを両方残します。
SKIPした処理には、適用を確認した記録は付きません。
親プロセス・HIPの一覧取得・Vulkanや、Windowsの永続的な環境設定は変更しません。
モデル・計算精度・デコード設定も変更しませんが、コンパイルやロード、ウォームアップが長くなる可能性があります。
AMD実機でのクラッシュ解消と、常駐推論への性能影響は引き続き検証が必要です。

## CT2とwhisper.cppの比較条件

0.3.0以降は、両エンジンで同じ音声から共通の128×3000のfloat32メル特徴量を作り、
その入力ハッシュ・形状・元音声長を照合します。モデルは対応を確認したFP16のlarge-v3-turbo一式です。

- モデルのロード・音声読み込み・メル特徴量の準備・ウォームアップは推論時間から除外します。
- 同じ常駐モデルでウォームアップ1回の後、既定で3回計測します。
- 計測区間は、準備済み特徴量を使うエンコーダー・デコーダー処理からUTF-8テキストの取得完了までです。
- 英語の文字起こし、greedy、beam 1、温度0、履歴・タイムスタンプ・VADなし、4スレッド、生成上限128トークンにそろえます。
- 最短値と中央値を記録し、エンジン間の速度比には**中央値**を使います。

`Matched Whisper GPU comparison`は、CT2の実効FP16とVulkanが同じ物理GPUを使ったと確認できる場合の比較です。
`Matched Whisper CPU comparison`では、CT2 CPU float32とwhisper.cpp CPUを比較します。
内部の計算方法や重みの保持形式まで同一という意味ではありません。

`vulkan_over_ct2_median`は「Vulkanの中央値 ÷ CT2の中央値」です。
1より大きければ、その計測ではCT2の方が速かったことを示します。
条件・モデル・認識結果・共通入力・CT2のキャッシュ無効化確認がそろわない場合は、速度比を出しません。
0.1.0のプロセス全体時間や、旧版の異なる計測条件とは直接比較できません。

CT2 INT8_FLOAT16、CPU INT8、NLLB、同じモデルへの2スレッドからの呼び出しは、追加の動作検証です。
これらを上記のFP16の対応ペアへ置き換えて比較することはありません。
同梱音声以外の認識結果は、文意も含めて人が確認してください。

## 同梱物と任意の翻訳テスト

実行ファイル、CT2 ROCm DLL、HIPライブラリとカーネル、Vulkan版whisper.cpp・llama.cpp、
WhisperのFP16モデル2形式、NLLBモデル、ライセンスを同梱しています。
一部のファイルだけを渡さず、フォルダー構成ごと配布してください。

llama.cppでの翻訳には、別途用意する互換性のあるローカルGGUFモデル
`models/translation.gguf`が必要です。この任意モデルは同梱していないため、通常はその推論がSKIPになります。
NLLBとllama.cppは異なるモデルなので、両者の速度を同条件として順位付けしません。

同梱NLLBモデルは**CC BY-NC 4.0（非商用利用のみ）**です。
`licenses/`と`hip/licenses/`などのライセンス文書も一式に含めたまま配布してください。
任意に追加するモデルは、そのモデルのライセンスも確認してください。

## 自分の音声を使う場合

標準の`run.bat`では同梱の合成音声を使います。任意の音声を試す場合は、展開先で次を実行できます。

```powershell
.\vrct-amd-check.exe --audio C:\samples\speech.wav --runs 3 --timeout 900
```

音声は**16 kHz・モノラル・PCM16のWAVで0.2～30秒（3200～480000サンプル）**にしてください。
範囲外の音声は拒否し、長さを合わせるための暗黙の追加・切り捨てはしません。
ネットワーク上のパスは受け付けません。相対パスは実行ファイルの場所を基準に解釈します。
指定した音声の認識テキストがレポートに残るため、共有可能な内容を使ってください。

`--help`で追加オプションを確認できます。
`--stage a|ab|abc`はROCm側の検証段階を制限する指定で、Vulkanを停止する指定ではありません。
通常の協力者向け検証では、オプションを追加せず`run.bat`を使用してください。

ビルド手順・固定した取得元・モデルハッシュ・保守者向けの検証方法は[英語README](README.md)に記載しています。
